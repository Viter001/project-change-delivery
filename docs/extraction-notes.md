# 第一版提炼依据

日期：2026-10-26。用户目标：将已有项目管理经验泛化为其他项目可用的 skill；授权新建独立项目并形成一版。

## 来源与抽象

来源为同级 INTERACTIVE-NARRATIVE-SYSTEM 项目的 AGENTS.md、README.md 与 PRODUCT-DEVELOPMENT-LOG.md。这里只提炼方法；未重新验证来源项目产品行为。

| 来源经验 | 第一版规则 | 舍弃的局部细节 |
| --- | --- | --- |
| AGENTS 变更分级 | 依影响、依赖、可逆性决定流程轻重 | 固定命令、版本和提交要求 |
| AGENTS 保留原始需求 | 原件、整理结果、决策和当前状态分开 | 特定清单名称 |
| DEV-20261013-03 点击层修改导致滑动回归 | 按共享机制选择关联验证 | 页号及具体 DOM 实现 |
| 素材换源曾造成重复映射 | 保留来源与唯一映射，检查下游引用 | 素材表编号与原画规则 |
| 慢网测试错误使用文档完成作为就绪条件 | 用交付任务的实际可用状态验收 | 具体视频体积与网络速度 |

| DEV-20261022-05 长期失败检查未进日常门禁 | 对重复关键失败考虑轻量日常检查，更新过期预期 | 固定测试数量、行数上限 |

历史案例是提炼依据，不是未来任务的执行授权。第一版不引入预算、人员管理和排期算法，材料不足以证明这些能力。

## 设计选择

采用一个简短入口及两份按需参考。相比大而全的项目管理手册，此结构聚焦接收变更到交付接续；相比只复制协作规范，增加影响判断、证据语义与跨领域例子。

没有复制源项目脚本：它们依赖业务数据与目录。没有新增必填表单、固定审批节点或强制 commit。没有安装到全局 skill 目录。

GraphFlow context 已对新项目显式调用，返回空上下文，符合新建目录状态。plan schema 不支持 rootDir，按宿主规则未调用。会话内执行顺序：来源核对 → 场景基线 → 编写 → 结构校验与场景复核。

## 2026-10-26 用户追加规则

用户明确要求补齐缺失管理文件，并纳入来源 AGENTS.md 的四条规则。该要求取代第一版“不强制 commit”“小任务仅回复记录”的设计选择，历史提炼说明保留供追溯。当前入口已包含四条原始要求与执行说明，参考文档增加管理文件映射及占位标准。

## 2026-10-26 GitHub 术语调整

用户希望尽量采用 GitHub 名词并理解纯本地用法。新增默认 ISSUES.md、REVIEWS.md、DEVLOG.md，区分真实 PR 与本地草稿、Checks 与验收标准。四条规则保留，未把开发日志冒充 PR 或 Changelog。没有改名或迁移来源项目文件，没有创建远程仓库、上传代码或提交 Issue。

## 2026-10-26 Issue 双向同步

用户同意显式指令触发的上传、拉取、双向同步。新增 issue-sync 规程、记录结构、字段级三方比较、评论映射、操作日志及失败恢复。未指定实际仓库，故本轮仅编写可复用技能，不创建远程对象或本项目绑定文件。原“索引仅链接”改为默认模式，启用同步时允许基线管理的本地可编辑视图。

## 2026-10-26 轻量协作与中断接手

用户实际使用 dsh-crew，常见需求为 GPT 额度耗尽后由 DSH 核对成果并收尾。已按确认方案新增按需参考：委派边界、已有提交与工作区全貌、验证证据分类、子任务停止确认、过程恢复点。复用现有 Issue 和开发日志，不新增调度体系、不固定模型、不强制独立评审；共享暂存区的提交操作由协调者串行执行。

## 2026-10-26 按用户与 agent 分层记录

用户指出中断后供 agent 接续的实时日志不应混入普通用户日志。新增 record-layers 参考；DEVLOG 改为沟通、工作流与验证摘要，checkpoint 和必要原始输出进入按任务/运行隔离的 .agent/runs。取代此前将详细恢复点直接写 DEVLOG 的设计，历史说明保留。未迁移来源项目或清理已有日志。

## 2026-10-26 Question／Feedback 分类定稿

用户确认 Question 是重大变更和冲突裁决，原会议 Review 改称 Feedback。入口与所有参考统一 QUESTIONS.md／FEEDBACK.md，新增 Q／FB 编号及旧 REVIEW 别名保留；PR Review 仅指代码评审。Issue 同步增加 decision／meeting-feedback 路由、独立阶段、待分类区和分类迁移约束；不再强制重复 ISSUES 总表。仅更新规则，未迁移来源项目或真实 GitHub 标签。
