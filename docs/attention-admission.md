# 注意力请求准入与阶段验收

2026-11-02。用户已批准修正试用中的“修复—催验—再修复—再催验”循环。本规则补充 project-views-pilot.md；业务数据保留在试用项目，未发布新 skill 版本。

## 准入原则

交付结果与请求回应分别呈现。已交付可以告知，但不得自动追加确认任务。未人工验收不等于必须立即请求验收；移出当前注意力区不等于通过或关闭。

每个请求必须同时具备：

1. 为什么需要用户：Agent 无法自行替代的取舍、主观验收或外部条件。
2. 为什么现在：已发生的阻塞、已约定的阶段验收节点，或有依据的重要风险。最新发生、存在未关闭记录、刚做完修改均不足以构成理由。
3. 回答能解锁什么：明确下一步、交付判断或风险处理结果。
4. 具体行动、事实来源与定性注意力收益依据。不能只填“高”“影响体验”等通用文字。

缺一项则不得进入当前请求区；留在主记录、候选或交付摘要中。相同事项没有新增证据、触发变化或用户主动安排，不重复催问。对真实重大风险仍需及时提示，不以降噪掩盖。

## 三类输出

- 当前需要行动：通过准入的决策、约定验收与介入；计数从通过的请求生成。
- 近期交付：简短事实与证据，明确无需回复。功能和设置的保留项不堆入行动区。
- 阶段体验候选：非阻塞的主观细节按已有交付范围聚合，默认折叠。没有约定阶段验收时间时不能假造已到节点。

当前请求允许为零，显示“当前无需你立即介入”。有获准的后续工作就说明可继续内容；没有授权时如实记录待安排，不制造复验填空。项目主线来自阶段目标，不随最近一次细节修改重写。

## 注意力投资回报率

指标用于筛选而非包装提问。Agent 已能核实的事实、已确认决定、没有新增信息的重复确认，预期收益低，不发起请求。预期高收益须说明具体解除的依赖或阶段交付；实际回报只能由结果证明。已有验收可记为成果，不能据此虚构节省时间或证明减负有效。

按阶段复盘必要往返、解锁成果与重复提问；用户不另填计时表。探索尚未兑现不自动判为浪费。

## 验证场景

- 已确认默认值且已有验证：仅交付事实，零新增确认请求。
- 普通修复后未收到人工体验：保留未验收状态，进入阶段候选，不自动催问。
- 重大规则取舍阻塞已批准实现且无法由 Agent 决定：有依据地进入请求区。
- 用户已约定当前阶段验收且成果就绪：进入验收请求，逐项保留结果。
- 只有“高收益”或未来可能需要：拒绝进入当前请求区。
- 当前无合格请求：空状态正确，不能为测试通过硬填问题。

浏览器检查验证展示与交互；这些场景验证筛选规则。二者都不能替代后续真实减负效果评估。
