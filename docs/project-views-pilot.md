# 文件驱动的项目双视图：最小试用方案

日期：2026-11-02。状态：方案待审阅，尚未实现生成器或工作台；不升级 v0.2.0。

## 目标与边界

让使用者无需重读全部议题，即可把握项目整体，并知道当前需要自己决策、验收或介入什么。此次只读核对试用项目管理文档；本文件只保存通用设计，不复制试用项目的业务议题、状态快照或验收材料。

试用项目拥有自己的全部数据和生成视图；skill 项目拥有通用规则、模板和以后可能需要的生成工具。试用输出不依赖 skill 仓库内临时文件，不进入产品运行时。两仓库分开验证和提交。不得将试用项目本地管理资料自动上传 GitHub。

## 已选择路径与取舍

采用现有文件驱动、生成只读视图的轻量路径；GitHub 为中心和独立工作台留作未来选择。原因是避免用户同时维护第二个产品。第一轮决策和验收仍在聊天中完成，由 Agent 更新主记录后刷新视图。暂不做后台服务、数据库、写回按钮、自动调度或远程同步。

## 数据来源与职责

| 来源 | 用途 |
| --- | --- |
| 全局产品规划 | 长期目标、能力方向、范围边界；不据此自动承诺版本功能 |
| 版本规划 | 已确认交付范围与完成条件 |
| Questions | 关键裁决及其生效范围、触发条件 |
| Feedback | 整改与复验状态，保留原编号 |
| 验收记录 | 证据版本、环境、覆盖范围和未验证部分 |
| Devlog | 阶段成果，不从提交数量推导完成率 |
| Discussion log | 必要时追溯用户指令和批准依据，不作为日常主视图 |

每个事项仅一个完整主记录；视图是摘要和引用。来源冲突标为待核对，不能仅凭时间较新自动覆盖。当前主线若没有明确批准来源，标为 Agent 建议，不写成用户已确定。

## 全景视图

先展示长期目标、当前版本目标、已交付与未验收的区别，再按工作线展开能力、关联事项和依赖。阶段是对已有事实的整理，不虚构已批准的里程碑或期限。

默认收起历史细节；后续候选、暂缓事项仍可见其位置和重新触发条件。不显示无定义的进度百分比，不将全部 Issue 平铺为项目全景。

## 注意力视图

三类：决策、验收、介入。每项必须有“为什么现在需要人”“具体行动”“影响或延期后果”“证据/主记录入口”。决策附建议及取舍；验收附成果入口、条件与已知限制；介入附阻碍和已经尝试的处理。

优先展示真正阻塞当前已批准目标的事项和可执行验收。同一根因或共同决策合并呈现，但保留各原编号和独立结果。未进入当前版本的裁决放在“到条件满足时再处理”，不每日重新催问。风险或期限变化可提前进入注意力区，不能为了简洁隐藏阻碍。

没有紧急项就明确说没有已确认的紧急事项，不强凑任务。源文件互相矛盾先由 Agent 核对；只有影响用户决定且无法自行核实时才请求介入。

## 后续最小实现建议（尚未实施）

在试用项目本地的独立管理目录放一个自包含 HTML，提供两个页签和来源链接，不接入应用源码或菜单。配套摘要数据由 Agent 从原记录提炼，作为可重建的派生文件，用户不另行维护。

每次生成记录时间、来源文件相对路径与 SHA256、生成范围和未核实内容。刷新前核对源文件变化；旧页面显示快照日期并明确不是实时监控。后续刷新流程发现哈希变化时标为过期，不能假装静态 HTML 自己能监控文件。

浏览器可能限制本地 Markdown 跳转，保留可复制路径并验证实际可达性。视图继承原记录的本地保密与忽略规则；不能把本地数据嵌入可分发 skill 包。

## 试用验收

1. 用户能从全景说出当前目标、已有成果和主要缺口。
2. 从注意力视图直接知道要做的动作，无需先读开发日志。
3. 同一事项只呈现一次必要行动；批量验收仍能分别通过、拒绝或暂缓。
4. 延后事项有重启条件，已关闭事项不会因旧日志再次变成待办。
5. 每条结论可追溯到原文；未知与建议明确标注。
6. 改动主记录后刷新，两个视图一致；旧快照不能冒充最新状态。
7. 实现后检查桌面浏览器显示、切换、长文本及来源入口，之后才声称视图可用。

## 本轮记录与验证

用户提出两种视图并选择文件驱动路径，要求 skill 与业务项目隔离。本轮读取试用项目约定、规划、议题、验收和近期工作记录，完成来源映射与分流规则，未修改业务项目、应用代码、现有 skill 或安装副本。

发现的通用问题：待裁决不等于立即需要用户；未关闭反馈混合多种行动；历史状态与新结论需按范围核对。以上仅为文档分析，未复跑应用测试、查询 GitHub 当前状态或证明认知负担已降低。

## 注意力投资回报率与首版实施授权（2026-11-02）

用户确认制作首版。指标定义：阅读、判断、沟通和验收投入换回的有效推进；有效推进包括消除不确定性、解除依赖、确认成果和避免返工，不以提交数或关闭数替代。

区分预期收益与实际兑现，采用高／中／低／暂未兑现的定性判断，附理由和证据。暂不计算比例，不强制计时打分，不考核用户响应速度。探索未兑现不等于无价值。相互独立的验收结果不得因批量展示而一起关闭。

首版由试用项目保存只读静态 HTML、生成脚本、快照来源哈希和验证截图；不改变分发 skill 及已安装版本。通用规则继续留在本项目，业务数据不复制到此。

首版验证记录：试用页已在业务项目的独立本地目录生成。页签、键盘导航、来源展开、窄屏溢出和浏览器错误检查通过，桌面截图已查看；来源 SHA256 校验通过。仅确认原型可用，注意力回报仍待真实试用。无业务数据进入本仓库，skill 分发与安装版本保持 v0.2.0。
