# 变更分级与验证

从用户结果、依赖、可逆性和失败成本判断处理深度。

| 影响 | 合适闭环 |
| --- | --- |
| 局部展示或可逆细节 | 定向修改、相关验证、简记、提交 |
| 共享模板、交互或计算规则 | 沿直接依赖检查代表性使用方和边界 |
| 接口、标识、数据含义或对外承诺 | 明确新旧行为，核对授权、兼容、迁移和恢复方案 |

一项任务的不同部分可采用不同深度。依据影响选择范围，文件数量仅供定位。

精确契约（金额、标识、映射、批准文本）使用精确检查；可调表现使用源于目标的区间或行为条件。就绪条件匹配实际可用状态。界面、音视频、导出文档等检查实际交互或呈现效果；结构正确仅说明结构层证据。

记录当前版本、环境、输入、范围与结果；模拟和真实环境、历史与本轮结果分别说明。失败先对照有效需求判断：实现缺陷、过期预期、环境或输入问题，再修对应部分。有效要求保持成立，需求变更后同步更新预期。

既有问题由旧版本复现或可靠历史证据确认。阻断当前目标的缺陷按授权解决，其他事项记录影响并回到当前目标。覆盖充分且通过后停止检查；新增修改、失败或未解决风险触发补检。
