# 项目视图生成与维护

调整本流程时，以 [设计哲学](design-philosophy.md) 作为取舍依据。

在用户要求建立项目视图，或已采用视图的项目需要刷新时读取。展示与筛选原则见 [项目注意力](project-attention.md)。本文件是实现规范；使用者由 agent 在具体项目生成配套文件，skill 本身未附通用可执行生成器。

## 轻量落地

优先复用现有管理入口。新建时采用文件驱动、只读本地 HTML，放在项目独立管理目录（例如 docs/project-views/），让用户继续在当前工作会话反馈。业务记录仍为主记录，页面和摘要可重建。沿用项目存储、忽略和远程授权约定。

| 配套职责 | 建议载体 | 内容 |
| --- | --- | --- |
| 用户入口 | index.html | 默认注意力、全景及内嵌关系网络 |
| 派生摘要 | view-model.json 或等价载体 | 阶段、工作线、事项、请求候选、成果、阶段验收候选、关系 |
| 筛选与生成 | 项目适用的脚本 | 准入评估、计数、渲染、来源校验 |
| 来源清单 | sources.json | 生成时间、源文件相对路径及 SHA-256、生成范围、未核实内容 |
| 维护说明 | README.md | 主记录映射、实际命令、维护者、刷新顺序、验证方式 |
| 验证 | 项目现有测试工具 | 准入场景、来源一致性、浏览器交互 |

语言、文件拆分随项目调整；首次生成需要同时交付维护入口和验证方式。派生摘要由 agent 从来源核对维护，生成脚本负责确定性筛选与渲染，语义判断由 agent 负责。

## 页面组织

注意力页依次呈现：当前请求、近期成果（无需回复）、默认折叠的阶段验收候选。请求计数从通过准入的结果计算。零请求显示当前无需介入，并列出可继续的已授权工作或真实的待安排状态。

全景顶部显示「当前阶段」，用两句话回答「要解决什么」和「正在做什么」。第一句写核心问题或待澄清的不确定性，第二句写针对它的实际行动；尚未开始的行动标为下一步。紧随其后关联直接服务于该问题的议题，其他工作线留在全景。

探索期可以只写当前问题和探索行动，后续阶段等方向明确再写。普通修复更新行动与证据；新证据使原问题更明确时收窄表述。团队决定转向另一核心问题时，引用决定来源，把上一阶段取得的结果和转向缘由简记入阶段成果，供回看里程碑。已有长期目标、完成条件及已交付和未验收成果随来源展示。后续候选和暂缓事项保留位置与重启条件。主线来自有效规划或决定，建议明确标注为建议。

关系网络放在全景内，以稳定事项 ID 标识节点，边注明依赖、阻塞、关联或取代及其来源。支持节点聚焦、邻居与边含义、拖动、缩放、复位；提供可用的文字关系列表与键盘入口。独立节点保持独立，历史项标明历史。批量展示保留每项独立验收结果。

用户界面以项目事项和行动为主，机制解释集中在维护说明。源记录入口提供可复制的相对路径和条目定位；本地浏览器链接受限时仍可定位原文。

## 最小数据约定

所有摘要保留稳定 ID、来源路径及条目定位。可采用以下字段或语义等价结构：

- stage：核心问题、当前行动、来源；已有阶段目标、完成条件和批准依据按实填写；workstreams/items：阶段归属、真实状态、下一步。
- requests：id、issueIds、type（decision/acceptance/intervention）、action、whyHuman、whyNow、unlocks、sources、trigger、benefitBasis、attentionCost。
- trigger：kind（blocking/agreed_acceptance/important_risk）、实际触发依据与可核实时间；约定验收记录其批准来源。风险分别记录当前需处理的依据、决策截止时间和预期损害时间，以当前需行动的时点判断准入。
- 请求复核事实：agentVerifiable、previouslyAnswered、newEvidence；重复问题的新证据引用来源。
- deliveries：成果、实现／验证／验收各自状态、证据、无需回复标识。
- stageCandidates：待体验事项、所属阶段、验收条件和已有约定节点；未知节点明确待安排。
- relations：from、to、type、source；节点身份与事项身份一致。

准入函数返回合格请求和其余候选的理由。缺少行动／来源／需要人／现在触发／解锁结果／收益依据的候选保留在主记录或候选区；未来触发、代理可验证、无新证据的已答问题同样进入候选而非当前请求。重要风险的“现在”指风险已被识别且需要当前处理，损害可以尚未发生。仅填“高收益”等通用标签不足以通过。

程序能检验字段与状态，事实及收益依据仍需核对原文。ROI 定性比较收益与阅读、判断、切换成本；区分预期与实际兑现。阶段复盘参考已发生的解锁成果、必要往返和重复请求，使用已有记录即可。

## 刷新与跨会话接续

1. 在推进该项目的会话更新规划、Q／FB、验收及阶段记录，保留原批准范围与真实验收状态。
2. 对照旧来源清单检测变化，读取变化来源，核对仍有效的阶段目标和未决事项；冲突先核实，必要时标待核对。
3. 更新派生摘要、成果与阶段候选，核对关系，再评估请求准入。单纯改时间或哈希不足以完成这一步。
4. 主记录稳定后保存旧来源清单的可恢复副本，生成新页面和清单。生成期间来源改变则重新核对，使输出和来源对应同一快照。
5. 校验来源、请求计数、关系引用与页面；界面改动时执行浏览器检查并查看截图。报告快照时间及未验证范围。

静态页面显示快照时间；浏览器刷新仅重载页面。来源过期由刷新／检查流程识别并报告，实时检测需另外实现。

项目 AGENTS.md 或等价入口登记视图路径、维护说明及刷新责任，让新会话可从文件接续。维护者按现有授权安排，同一时刻一位写入者；工具不可用时报告待刷新及原因。通用 skill 维护会话仅维护机制，业务项目保存自己的状态、脚本与证据。

## 验收清单

- 来源：路径和条目可定位，哈希与实际文件一致；模拟源改变能检测过期；派生摘要与原记录语义核对。
- 准入：验证缺字段、未来节点、代理可验证、已答无新证据、空泛收益；验证真实阻塞、约定验收、当前需要处置的重要风险；零请求正常。
- 状态：解决后移出请求仍保留真实验收状态；阶段目标在局部修复后保持；批量验收可分别通过、拒绝或暂缓。
- 展示：默认注意力、成果无需回复、候选折叠、全景网络、关系含义、聚焦／拖动／缩放／复位、键盘、长文本与窄屏。
- 交接：新会话能依据维护说明找到主记录和刷新方式；输出在业务项目自包含，不依赖 skill 源仓库。

行为测试与浏览器检查分别记录；原型可用与实际降低注意力成本分别评价。

## 事项清单

在全景的事项清单中先分 Q／FB，每组内提供 Issue 类型筛选并保留类型待定的条目。每行引用主记录，显示下一步行动或复评条件及真实落实状态。该分组用于浏览，注意力请求继续按行动准入筛选。
