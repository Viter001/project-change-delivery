# 协作与中断接手

委派在用户授权内使用现有工具。派发写清目标、完成条件、必要背景、文件或职责归属、已有成果与返回证据。独立任务可并行，依赖或重叠写入按顺序处理。共享工作区由协调者统一暂存、提交和更新管理文件；独立 worktree 分别提交后核对集成。

根据工具状态和实际成果判断完成。工具迟迟无结果时先查看状态与输出，再决定等待、停止或接手；重新派发前确认旧执行者已停止重叠写入。复核力度按任务风险确定。

## 接手顺序

1. 从最新用户要求、有效决定及成果摘要恢复目标，再读 checkpoint。
2. 确认前任及其子任务的写入状态；状态不明时先做只读核对和无重叠工作。
3. 确认具体项目、分支与任务起始 BASE，检查 BASE..HEAD、暂存、未暂存及未跟踪成果。任务可能跨多个提交；BASE 不明时通过相关历史定位并注明不确定性。
4. 保留用户及其他执行者的成果。已完成且证据仍适用的直接接续；已实现但证据缺失的补验证；未完成的继续；无关修改留在原处。
5. 检查受影响范围，更新记录并为本次相关成果创建中文提交。只读核对无需空提交。

历史证据注明来源、范围和环境；后续修改影响证据时重验。既有问题若阻断当前目标，仍作为交付阻碍处理。

恢复点在有意义的进展时持续更新，内容和保存方式见 [记录分层](record-layers.md)。缺少恢复点时依据目标、文件和实际状态重建，再继续工作。
