# 管理记录

| 内容 | 主记录 | 最小内容 |
| --- | --- | --- |
| 产品能力、设计、版本范围 | 已有规划／规范 | 当前有效目标与边界 |
| 重要取舍、范围变更、规范冲突 | QUESTIONS.md，Q-编号 | 决定什么、影响什么、谁决定、依据与落实状态 |
| 反馈与整改 | FEEDBACK.md，FB-编号 | 当前问题表、现象、期望、整改和验收证据 |
| 阶段成果 | DEVLOG.md | 改变、验证范围、限制、关联事项 |
| 实质对话推进 | DISCUSSION-LOG.md，D-编号 | 日期、用户提出、回应／处理、结果和引用 |
| 执行现场 | agent 运行目录 | 恢复摘要、必要输出和证据 |

同一事实在主记录完整维护，其他位置摘要并链接。按实际变化更新相关记录。

## 入册与清单

Q 的入册条件是存在有影响的选择或冲突，能够写清决定和影响。普通需求进入规划，执行指令进入讨论记录。同一决定多轮讨论更新同一个 Q。顶部只列当前待决事项，已决区保留结论、理由、适用范围、批准来源和落实状态；新决定取代旧决定时显式关联。

Feedback 顶部始终保留当前问题表：编号、用户可见现象、状态、下一步／阻塞、详情链接。详情维护来源、期望、整改、复验及关联 Q。清单和详情同次更新，远程同步只以详情身份处理一次。超出已批准范围时关联独立 Q，裁决后继续原 Feedback。已完成或取消项归入关闭区并保留理由、证据和索引。

DEVLOG 按阶段或有意义的工作单元更新；DISCUSSION-LOG 按实质轮次更新。“继续”等消息并入原条目。区分建议、批准和执行；日期依据实际来源。长输出链接到 agent 记录，正式证据单独持久保存。阶段日志与对话日志通过链接关联。

## 迁移

实际项目迁移遵循用户授权。保留原件和旧编号映射：普通对话型 Q 可转入讨论记录，原位置留重定向；有效裁决保留身份和 GitHub 绑定；旧 REVIEW 编号保留或设别名。归档保留历史与入口，未知状态写待核对。升级 skill 的授权仅涵盖 skill 本身。
