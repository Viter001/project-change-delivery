# 记录分层

用户记录呈现目标、决定、成果、验证范围和剩余影响，分工见 [管理记录](management-records.md)。正式验收证据存项目持久位置，例如 docs/evidence/<task-id>/，由记录链接。

agent 恢复现场按需放 .agent/runs/<task-id>/<run-id>/：checkpoint.md 为入口，logs/、evidence/ 和 events.jsonl 按实际需要建立。复用现有工具日志；跨宿主接手时把必要摘要保存到接手者可读的位置。

checkpoint 记录时间、执行者、项目／分支／工作目录、可确定的 BASE/HEAD、已有成果、对应验证、剩余工作、下一步、运行中的子任务和证据入口。缺少基线明确写未知。关键提交、验证、方案变化或阻塞后更新；以原子替换等方式保护完整性。

每个执行者写自己的 run，协调者汇总共享记录。接手创建新 run 并引用旧 run，先确认重叠范围的旧写入已停止。恢复顺序：目标与决定 → checkpoint → 相关差异和必要日志；实际工作区和工具状态用于校正过时摘要。

运行目录默认本地保存，可把精确路径 .agent/runs/ 加入已有忽略规则。跨机交接按授权传递必要摘要；正式记录遵循项目提交政策。忽略规则仅控制版本管理，不提供访问控制。日志仅保存工作事实和必要输出，不记录密钥或内部隐私推理。

运行历史清理依据明确保留策略或清理授权，保留活动运行、唯一恢复点和未归档证据。极小且无需接续的工作直接使用已有记录。
